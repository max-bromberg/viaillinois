# Changelog

All notable changes to VIA are recorded here. Versions follow semantic versioning.

## Unreleased

- The first download is a third of what it was. Every page of the site was in it, so a student opening the feed fetched the logistics dashboard, the intelligent scheduler, the poster designer and the markdown and QR code libraries before seeing a single event. Each page is now its own file, fetched when somebody opens it, which takes the first download from 404 kB to 106 kB, or 122 kB to 38 kB over the wire. A page that cannot be fetched, which happens to a tab left open across a deploy, now says so and offers to reload instead of leaving a blank space.
- A visit no longer waits on the answer to who is looking before drawing anything. The whole screen, and the feed's own request, used to sit behind that round trip. Pages that exist only for somebody signed in still wait, because drawing one before the answer arrives sends a board member to a login page they are already past. The account area of the navigation bar stays empty until the answer comes, rather than showing Sign in and correcting itself a moment later.
- Responses are compressed, and the ones that can be cached say so. The CDN now fetches from Champaign compressed, so every cache miss travels a fraction of the bytes. Nothing the API answers is stored by a shared cache unless the route says otherwise, because most of it depends on who is asking, and the two that do not, the kiosk listing and the term calendar, can now be answered at the edge, as can the sitemap and the files crawlers read. The document itself is checked every time, because it names the files this build produced.
- The events feed has an index to read from. Every feed query reads public events by when they start and sorts them the same way, and none of that had an index, so each one read the whole table and sorted it. It did not show while events were entered one evening at a time; recurring events turn a term of weekly meetings into about sixteen rows apiece, so the table now grows by the term.
- Two dependencies carrying high severity advisories are updated, one of them the MySQL driver, where the advisory is an authentication plugin downgrade that leaks the database password in plain text. Both were fixed within the versions already allowed, so nothing about how they are used changes.

- Events can repeat. A weekly meeting, a fortnightly design review or office hours on a Tuesday and a Thursday is now one thing to set up rather than fifteen, and it can be created three ways. The event form has a repeat: every week or every other week, on the days chosen, until a date that starts at the end of instruction and can be changed. A calendar file whose entries carry a repeat rule is expanded on import, where before a repeating entry was imported as its first occurrence and nothing else, which is how a board could import a term and end up with one event. And the scheduler can be asked which evening works for the rest of the term rather than which evening works next week: it scores a weekday and an hour across every week it would run, says how many of those weeks are clear, and creates the whole series when a recommendation is accepted. The repeat runs to the end of instruction and skips the weeks with no classes, read from a university calendar VIA now keeps, and every screen shows the date it arrived at so an organizer can correct it. Editing or deleting one week of a series asks whether that week, that week onwards, or the whole series was meant, and a week changed on its own stays changed when the rest of the series moves later.
- Editing an event that had a room no longer fails. The check for a double booking called a helper the module never imported, so saving any event with a room and a time answered with a server error instead of saving. Editing an event from the dashboard also no longer clears its room: the listing behind that form did not carry the room's identifier, so saving an untouched form removed the booking.

- RSVPs are removed. The RSVP card on the event page, the Going and Maybe buttons on every event card, and the two endpoints behind them are gone, along with the calls the browser made to them and the copy elsewhere on the site that offered the feature. Anything still asking for those two addresses is answered with a 404, rather than being led to believe it recorded something. The RSVPs table is left where it is, holding what was recorded, since dropping it would throw away the only copy and nothing reads it now.
- The events feed opens on what is still to come. It listed every event VIA had ever held, oldest first, so the first page a student landed on was full of talks and socials from previous terms and the events happening this week were pages deep. The feed now starts at the beginning of the campus day, which keeps an event that began this morning on the page for the rest of the day, and everything before that moves into an archive. The archive is a click away in the filter panel, under When, and it reads most recent first, which is the order somebody looking back through the term wants. The calendar is unaffected and still shows whichever week or month it is pointed at, including the ones that have passed. The front page that search engines and assistants read now lists upcoming events too, which is what its heading always claimed.

## 0.4.0 (2026-09-01)

- Every time on the site is now campus time, and one clock decides it. A stored time is the wall clock the organizer typed, and it was being read back by the database driver as an instant in whatever zone the server container had started in, published as UTC, then rendered by the browser in whatever zone the reader was in. Neither of those two conversions is campus time, so the hour an event showed depended on where it was read from and on how the container happened to be started. Times now leave the API with the campus offset attached, which names one instant, and the pages render that back on the campus clock, so a student reading the feed from home over the winter break is shown the hour they would have to turn up at in Champaign. Both containers also run on campus time, so a timestamp the database writes for itself sits on the same clock as the event times beside it.
- Whether a midterm reads as upcoming, ongoing or past is now decided against the campus clock. It was decided by MySQL's NOW(), which is the database container's clock, so the answer was five or six hours away from the exam and the listing hid or kept the wrong entries around the turn of the day. The same fix applies to the upcoming events on the kiosk and to the confirmed midterms on the calendar.
- The scheduler recommended the wrong times. It published each slot converted to UTC, so a slot found for six in the evening was offered as an hour that depended on the container rather than on the campus clock, and it asked for the midterms in its lookahead window using a bound converted the same way, so it weighed the wrong window of exams. Both now work in campus wall clock.
- The calendar asked the server for the wrong week. The week it displayed was converted to UTC before being sent, which moves it to the previous day for any reader west of UTC, so the week shown and the week fetched could disagree. Events also sat in the wrong column and at the wrong height on the week grid, because the grid placed them by the reader's clock rather than the campus one, which slid a late evening event into the next day.
- An event edit form is filled with the hour the organizer typed. It was filled from the published instant read in the reader's own zone, so opening an event and saving it without touching anything moved it.
- A midterm can be deleted, not only cancelled. Cancelling keeps the row, which is right for an exam that was scheduled and then called off, and wrong for one that should never have been listed, which until now stayed in the admin listing forever. Deleting asks for confirmation first. One thing is worth knowing and the page says so before you delete: a midterm that came from the HKN calendar is added back by the next import of that calendar, because the import matches entries on the identifier the calendar gave them and finds nothing. Cancelling is the way to keep one of those off the schedule for good.
- Importing midterms from a calendar file is open to global admins and to anyone who sits on an RSO board, rather than to global admins alone, and the panel is now on the midterm schedule as well as on the admin page. It was previously reachable only from the admin page, which a board member cannot open, so from a board member's seat the feature did not exist at all, even though the boards are the people who read that schedule. An ordinary member still cannot import, and neither can an editor. Importing events is unchanged and still needs board or editor access to the RSO it writes to. Every import still previews first, so nothing is written unseen.
- The calendar import panel now says when it has written something, and the listing behind it reloads. It previously left the table showing the schedule as it stood before the import, which read as an import that had done nothing.
- Deleting a midterm is open to global admins and to anyone who sits on an RSO board, rather than to global admins alone. The schedule belongs to no single RSO, so there is no RSO to be on the board of for a given exam, and sitting on any board is the bar. Boards are the people who plan around this listing and so the people who notice what is wrong with it, and a board that spotted a duplicate previously had nobody to tell but an admin. An ordinary member still cannot delete, and neither can an editor, whose remit is that RSO's own events. Board members cannot open the admin page, so for them the control is on the midterm schedule itself, where it reaches the exams that listing shows. A global admin still reaches the whole history from the admin page.

## 0.3.0 (2026-09-01)

- Events and midterms can be imported from an .ics calendar file. The file is read in the browser and its text is posted, so there is no upload endpoint and nothing is written to disk. An import previews first: it lists what it would create or update, which room each entry resolved to, and what it could not read, and writes nothing until that is confirmed. Importing the same file again updates what the first import created rather than duplicating it, matched on the identifier the calendar gave each entry. Rows entered by hand carry no such identifier and are never touched. A location is only claimed as a known room when the text names both a building and a room number, so ECEB 1002 resolves and a bare 1002 stays as written. Midterm entries have their course read out of the title and are imported as confirmed, since HKN is the authority; titles naming no known course are reported rather than guessed at.
- Midterm crowdsourcing is gone. The votes table and the trigger that confirmed a midterm once its score reached five are dropped, along with the vote endpoint and the vote column in the listing. Midterms now come from HKN, so a midterm can have no submitting user.
- An RSO board can add people who have never signed in. Paste a list of NetIDs or Illinois addresses and the roster is recorded straight away; anyone without an account gets a placeholder row carrying no name and no email, marked as invited, and they find themselves a member the first time they sign in. Entries that cannot be a NetID are reported back rather than silently dropped.
- An event's location is now optional, and can be a room VIA knows about or free text for anywhere else. The venue finder that asked for expected attendance and ranked rooms by capacity is gone, replaced by a search box that understands building codes: typing ECEB, eceb1002 or electrical all find rooms stored under the full building name. Events with no room now appear in the feed and on the kiosk, which they would not have done before, because every listing query joined the Locations table and an inner join drops exactly those rows.
- Standard security response headers are sent on every response: nosniff, SAMEORIGIN framing, a referrer policy, and strict transport security in production only. The framework banner is no longer advertised. No content security policy is set yet, because writing one by guesswork either blocks the site or permits everything.
- Member email addresses are shown only to the board of that RSO and to global admins. They were previously returned to any signed in user, which at UIUC is every student.
- The three endpoints that can be asked to do a lot of work per request are now bounded: a calendar import is capped at a thousand entries and rate limited, the calendar endpoints accept a larger request body than the rest of the API so that a real year of events does not fail with an opaque error, and a pasted roster is capped at two hundred people.
- A pasted roster is no longer split on spaces. A spreadsheet column of names beside addresses used to become one account per word, so pasting Jane Doe jdoe2@illinois.edu created accounts called jane and doe. A field containing spaces is now reported back instead of guessed at, and a header row is ignored.
- The circuit background is reworked. It no longer animates on its own: the previous version spawned a pulse somewhere on screen about twenty five times a second, which competed with the page for attention. The board is now still and faint until the cursor reaches it, and touching it sends current out from the nearest pad, spreading through the traces and fading as it goes, so the only motion is where you are already looking. Traces are routed with 45 degree chamfered corners the way a real board is, they take their resting colour from the active theme, and they carry current in Illinois orange. The canvas fades out behind the content column. Reduced motion is respected, and the animation loop stops when nothing is lit and when the tab is hidden, which matters for the kiosk that runs this on a lobby screen indefinitely.
- The site can be indexed. Every address used to return the same empty document with the same title, nothing in the body, and no link to any event page, so search engines had nothing to rank and crawlers that do not run JavaScript, which is most of the ones behind assistants, saw an empty site. The server now fills the document in before sending it: a title and description per page, a canonical address, sharing tags with a real card image, schema.org structured data, and a readable summary of the page that the application replaces when it starts.
- Event pages carry schema.org Event data, including start and end times with the campus timezone offset, the organizing RSO, and either the room or an online location. This is what search engines need to list an event with its date and place, and what assistants read instead of rendering the page.
- The sitemap and robots.txt are generated rather than shipped as fixed files. The sitemap now lists every public event rather than four pages, and uses absolute addresses, which the sitemap protocol requires and the previous file did not, meaning every entry in it was rejected. Internal events are excluded and carry noindex, as do the signed in areas.
- There is an llms.txt describing the site for assistants, and robots.txt names their crawlers explicitly, since several only index a site that says so.
- Built assets are served with a long cache lifetime and everything else revalidates hourly.
- The privacy policy and the terms are rewritten. The old privacy policy stated that the platform ran on Google Cloud with its database on Cloud SQL, which stopped being true when VIA moved to a single virtual server, and it described neither the placeholder records created when a student organization adds a member before that person has signed in, nor the database backups, nor the fact that event pages are now indexed by search engines and read by search assistants. All of that is now stated. The terms gain a plain statement that VIA is not a University service and is not endorsed by it, a licence covering the content organizations post, a copyright complaints route, disclaimers and a limit of liability, an indemnity, and Illinois governing law with a thirty day period to settle a dispute by asking first.
- The beta banner is gone from the top of every page.
- The "VIA is Live" platform update is removed.
- The About page carries a contact address, and the privacy policy and terms name it directly for deletion requests, copyright complaints, security reports and disputes, rather than pointing at a page that had no way to reach anyone on it.
- The background pollers can be switched off with POLLERS_ENABLED, so a local instance does not scrape Course Explorer and Ad Astra every time it starts. They stay on unless the value is exactly false or 0.
- A preview database for local development, with its own compose file, its own port and its own fixtures. It is built by npm run dev:db and described in docs/development.md.

## 0.2.3 (2026-08-31)

- The database no longer sits on the shared network named internal. That network carries every stack on the production host, Compose gives each service the alias of its own name on it, and three stacks there run a service called db, so the name resolved to three different servers and each connection was a draw between them. The database now sits on a network private to this stack under the name via-db, which no other stack answers to. This is the cause of the intermittent access denied errors on the public feed.
- A failed database restore now reports the error the client gave. The dump was piped into the client with no error handler on that stream, so when the client rejected a statement and stopped reading, the resulting write failure became an uncaught exception that killed the process before the exit code and the message could be read. Every restore failure surfaced as an unexplained EPIPE, including during a cutover and during a rollback.

## 0.2.2 (2026-08-30)

- The compose file now declares the external network named internal that the reverse proxy uses to reach the application by service name. It was previously an edit that existed only on the production host.
- A test guards the compose file against the three ways it has drifted or could drift: a schema mount into docker-entrypoint-initdb.d, a missing host backup mount, and a missing external network. The gate runs it.

## 0.2.1 (2026-08-30)

- The release gate now runs on pull requests to main and on version tags, and its three jobs are required by branch protection.
- The database schema is defined by migrations under server/db/migrations, applied by a locking migration runner, with a drift check in the gate.
- Deploys go through scripts/cutover.sh, which takes a verified backup, applies migrations, checks health, and rolls back on failure.
- The health endpoint is a real readiness check, and it reports the application version and the applied migration version.
- The root, server and client packages report one platform version, kept equal by a test in the gate.
- User facing copy and documentation no longer contain em dashes or en dashes, enforced by npm run check:language.
